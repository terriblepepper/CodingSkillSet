# 操作规则

以下为通用治理基线；项目事实、命令和边界在当前项目 guide 的 rules/project-map.md 维护。
用户当前明确指令优先于旧记忆、贡献指南的默认流程和 skill 默认保存目录，不据此绕过环境权限。

## 项目专属规则

首次引入必须创建 guide 的配套文件、目录及唯一的项目 skill 安装目录。
`Agent_Operate_Guide/rules/project-rules.md` 首次创建为零字节空文件；只有用户明确指令才能向其添加
项目专属约束。通用规范仍由本技能提供，源码事实写入项目地图；不擅自生成专属约束。
已有规则和用户修改不能因补齐配套文件而覆盖或清空；新指令就地增量维护，避免同义规则重复。
项目内技能包仅保留在 `.agents/skills/project-governance/`，guide/rules 只保存项目规则和地图。

## 先理解再改

1. 查看 `git status --short`、未暂存和已暂存 diff，识别用户已有修改，确定本轮边界。
   不覆盖、回滚、暂存或提交不属于本轮的修改。
2. 沿“入口/调用者 → 业务规则 → 状态/存储 → 外部边界”逐层阅读相关源码、所有调用方、
   数据结构、配置、前端消费方和测试。确认现状、根因、职责归属和影响后再修改。
3. 在拥有该业务决策的模块修复，保持高内聚低耦合，复用稳定接口；不创建反向依赖、循环导入、
   重复业务规则或仅供未来使用的泛化框架。跨模块修改先画出最小依赖/数据流。
4. 核对权限隔离、状态机、事务、幂等、取消、资源释放、兼容与回退，保留已有校验和异常语义。
   结构调整须有本轮实际收益，不能顺手重构无关模块。

## 必须使用的 skill

使用前读取可用的 SKILL.md，简要说明用途，只加载本轮相关内容。

| 场景 | skill |
| --- | --- |
| 编码任务入口 | superpowers:using-superpowers |
| 新功能/行为设计；复杂实施计划 | superpowers:brainstorming；superpowers:writing-plans |
| 缺陷/测试失败/异常行为 | superpowers:systematic-debugging |
| 新增或修改非平凡业务逻辑 | superpowers:test-driven-development，针对改变的行为先写失败用例 |
| 编码完成前 | brooks-review，范围限本轮 diff 与直接上下文 |
| 模块职责或依赖方向改变 | brooks-audit，范围限相关模块；导航用 onboarding 模式 |
| 技术债/测试质量专门任务 | brooks-debt / brooks-test |
| 新建或更新 skill | skill-creator、superpowers:writing-skills |
| 声称完成前 | superpowers:verification-before-completion |

Brooks 先诊断后补救；问题按“症状 → 来源/原则 → 后果 → 最小修复”附源码证据。
不因长度或风格偏好重构，不机械调用全部技能或发起全项目扫描。缺少必要 skill 时先运行本包 `scripts/install-deps.sh`（全局已有的依赖会自动跳过），
仍缺失则告知用户，不能冒称使用；继续独立调查，不偷偷放松要求。

## 正式文档

- 修改前后核对 Git diff 与新增文件，依据本轮真实行为变化决定文档更新范围。
  已忽略的正式文档需在本任务 tmp 保存相关原文快照后比对，不能仅凭 Git 无差异断言未修改。
- 优先更新已有专题的旧段落、删除过时说明；只在没有合理归属时新建专题并补导航。
  README 保持概览与入口，详细语义在唯一对应专题维护，重复内容用链接替代。
- 接口、配置、用户流程或运维改变时更新对应说明；纯内部调整且文档仍正确时不硬改。
- 不把排查流水、按轮次的变更总结、计划或审查报告写入正式 docs；长期事实进 details，过程进 tmp。
  被忽略不表示允许删正式文档或 `git add -f` 上传。

## 临时信息与清理

- Superpowers 的设计/spec/计划/评审、Brooks 报告、agent 交接、一次性脚本、命令日志、
  测试报告和截图统一写入 `Agent_Operate_Guide/tmp/<任务标识>/`，覆盖 docs/superpowers、
  docs 审查报告、项目根目录、.superpowers 和系统 /tmp 等默认保存路径。
- 标明用途、负责 agent、待办和待清理清单；多 agent 使用独立子目录。
  不写密码、令牌、私钥或完整个人资料，不让临时文件成为运行依赖或长期交接的唯一来源。
- 运行成功、失败、取消后，先停止本任务进程并关闭连接和端口，再清理自己的临时数据、样本、
  缓存、截图、报告、日志与一次性脚本。优先复用项目现有测试隔离和所有权清理机制。
- 保留正式测试源码、必要回归用例、测试基础设施和正式文档；清理对象只限本轮所有权明确的产物。
  保留用户资料和其他活跃任务文件，不无差别清空 tests/docs/生产 data，不用 git clean -fdx。
- 先同步正式文档和精炼记忆，再删除本任务 tmp。无其他活跃任务时 tmp 应为空；清理失败报告具体残留。

## 测试

- 从“改动行为 → 直接调用/契约 → 回归用例”选最小验证集，优先实际相关节点，再按证据扩大范围。
  使用项目现有入口和隔离配置，小范围不为并行而启动大量 worker。
- 不因贡献指南或通用模板默认全量自检，运行整个测试库、全项目浏览器回归、重复构建或安装验证。
  用户明确要求全量时执行；新证据扩大直接影响范围时补对应测试并说明理由。
- 文档、忽略规则、skill 修改只检查格式、路径、发现/忽略行为及必要的定向情景，不跑无关业务测试。
  不为可逆低影响改动写只复述实现的测试。
- 通过后不重复凑检查；新修改或失败才重跑相关验证。未运行、失败、受阻如实说明，不将局部通过说成全绿。

## Git 与网络

- 保留既有代理/反代链路，不使用或新增 NO_PROXY、no_proxy、--noproxy，不清空代理变量，
  不用 git -c http.proxy=、curl --proxy ''、关闭代理继承等方式直连救急。
- 不私改代理、反代、证书信任、DNS 或 TLS 校验。继承配置会绕过代理时先告知用户，不自行改值后联网。
- 代理失败记录脱敏命令、目标主机、错误和已知配置来源，通知用户修补并停止依赖操作，可继续离线工作。
  确认是环境权限阻止时按工具权限流程申请，仍保留原代理配置。
- 只执行用户授权的提交、push、合并和发布；检查暂存边界，不强制加入项目 guide、记忆和本地技能入口。
  用户明确授权发布通用技能集合时，只发布技能包及其通用支持文件，不发布应用项目的实际记忆和私有地图。

## 收尾与维护

主 agent 按包内记忆协议逐轮提炼、检查压缩条件并清理；子 agent 仅交接，不单独登记轮次。
规范改变在对应规则处维护，避免多份同义规则漂移。
项目事实改变时同步其项目地图，不把地图或日志复制为通用技能规范。
