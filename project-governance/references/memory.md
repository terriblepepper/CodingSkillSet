# 分层记忆与全历史压缩协议

主 agent 在每轮最终回复前执行本规则。它不是自动运行的 hook，记忆不能替代当前源码核实、
用户当前指令或实际操作授权。**details 模块只维护一个信息文档 `details/memory.md`。**

## 单文档结构与分层读取

- 顶部 `## 索引`：少量当前有效约定、最新总结编号、近几轮编号与主题词、待办/阻塞。
- 后续 `## YYYY-MM-DD-N`：每轮提炼信息或合并全部历史后的总结。
  `YYYY-MM-DD-N` 是文档内部编号，不能把编号变成文件名或另建每日/每轮文档。

| 层 | 内容 | 读取策略 |
| --- | --- | --- |
| L0 | guide/README、rules/README、memory.md 的索引段 | 每轮先读；信息文档先只读索引 |
| L1 | rules/project-map、本协议、索引指向的最新总结条目 | 按需读取项目导航与汇总记忆 |
| L2 | memory.md 内相关日期/主题的编号条目 | 按主题词 `rg -n` 定位，再读取对应段落 |

启动时不全文加载信息文档。根据索引找到相关标题及起止行，只读必要条目；总结/压缩时才遍历全部历史。
记忆有冲突时，以用户最新明确指令和已核验源码为准；标明旧决定被替代，修正文内索引。

## 逐轮提炼与内部编号

1. 一轮为主 agent 针对当前请求完成的一次最终回复；进度消息、工具调用、同轮用户补充和子 agent
   回复不单独编号。纯咨询轮也提炼必要结论；子 agent 只向主 agent 交接。
2. 使用用户明确指定的时区，未指定则采用当前会话时区；不直接采用执行主机默认日期。
   编号例如 `2026-11-17-1`，N 为不补零正整数；当天首次为 1，后续取当前文档当天最大编号加 1，
   跨日从 1 开始。同一最终回复前修正其既有条目，不重复追加。
3. 多会话同时写入时，以原子创建 `tmp/memory-write.lock/` 等方式取得独占写入权，
   从最新文件重新读取和分配编号；写回与更新索引完成后释放并清理自己的锁目录。
   不覆盖并发新增内容，也不擅自删除他人活跃锁。
4. 条目保留用户目标/新约束、已核实事实、关键决策及原因、实际修改与入口、实际验证结论、
   未完成事项及下一步。区分事实、用户要求、推断；不复制流水、完整 diff、原始输出或秘密。
5. 更新文内索引；规则性结论写入 rules 对应位置并引用，避免每轮重复整份规范。
   旧验证结果标明日期和范围，不能证明下一轮代码已经通过。

## 自动触发条件

每轮收尾检查 `details/memory.md`：**文内编号条目数大于 30 次，或文档总行数大于 2000 行，
任一条件满足，就自动压缩全部历史。** 30 次和 2000 行本身不触发，31 次或 2001 行触发。
编号数量按对话提炼条目（次）计算，不按日期、文件数或工具调用数计算。
用户手动要求总结/压缩记忆时立即执行，与上述阈值无关。

索引保持精简，计入信息文档总行数；不另设字符数或索引长度触发条件。
单份治理说明超过 200 行或 16000 字符时合并重复说明，仍超限则按职责拆分并保留导航，
不得改变规范的约束强度。源码地图保持入口导航，不复制整份源码。

## 压缩的唯一完成状态

1. 取得独占写入权，遍历 `memory.md` 中**全部现存历史条目、旧总结、有效索引和本轮新信息**。
   分批提炼也必须覆盖全部历史，不能只处理最近几轮。
2. 将全部信息归并去重，保留仍有效约束、已核实事实、关键决定及原因、变更/证据入口、
   当前状态和全部未决事项；替代关系要讲清。压缩是语义提炼，不能仅截断或删旧信息。
3. 在本任务 `tmp/` 写完整替换稿：只包含精简索引和**一个新的 `## 当前日期-1` 总结条目**。
   例如 `## 2026-11-17-1`。新条目标明“全历史压缩总结”及覆盖日期，包含本轮信息。
   已有当天 `-1` 的内容必须先并入；不保留旧编号清单、旧条目或原文附录。
4. 核对关键事实和未决事项均已保留，确认没有并发变更，再用同文件系统原子替换写回
   `details/memory.md`。校验前保留原内容，不能先删除原文再尝试生成总结。
5. 校验文档仅有这一个最新编号、索引只指向它，**之前全部编号条目已移除**。
   不将旧记录迁移到另一信息文档、归档目录或长期备份；移除本次 tmp 草稿/原文快照并释放锁。
6. 总结就是本轮唯一条目，不再额外追加一条；同日下一轮从 `-2` 继续。
   压缩后仍超长时继续提炼这一个总结，不能通过拆分历史文档规避阈值。

## 条目示例

```markdown
## 2026-11-17-1
- 主题：项目治理。
- 用户要求/约束：本轮新增或修正的关键点。
- 事实/决策：结论、理由和源码入口。
- 实际修改：文件入口及行为变化；没有代码改动也明确写出。
- 验证：实际命令、范围、结果；未执行项及原因。
- 待办/阻塞：当前剩余工作及继续所需信息，没有则写无。
```
